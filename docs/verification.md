# BenchKitMap 验证记录

使用 README 中的命令复现，输入为合成工作坊物料和报价。

| 操作 | 可独立核算的结果 |
| --- | --- |
| `plan examples/workshop.json` | 现场批次 6 套中可配齐 4 套，桌面批次 8 套中可配齐 2 套。传感器共需 14 件，库存 6 件，净缺口 8 件。 |
| 同一清单导出采购 CSV | 传感器 3 件包与 5 件包各一包，共 1,790 分。加上电路板 500 分、线材 700 分、螺栓 120 分，已报价合计 3,110 分。机壳 2 件待询价。 |
| `project examples/workshop.json` | 假定已报价采购全数到货，现场批次仍只能配齐 4 套，桌面批次可配齐 8 套。 |
| 盘点 CSV 将机壳更新为 6 个后重新规划 | 现场批次可配齐 6 套，先用完 6 个传感器，桌面批次暂可配齐 0 套。 |
| 现场批次实际领用 3 套 | 新快照的传感器库存为 3，现场批次还待领 3 套。再规划时两批分别可配齐 1 套和 2 套。 |

算法核对点。套件图在展开时检测环，共享子套件缓存其单位用量。采购先计算库存净缺口，再以最少总价、超买量、包数为依次优化目标。对于多种包装，最优订购量不会超过缺口加最大包装量减一，否则能去掉至少一个包装，费用不增且超买量更小。共同因子缩放减少搜索状态，单一包装直接取整。

测试覆盖共享子件、未被引用的坏依赖、数量超限、库存优先级、64 组采购组合的穷举对照、未报价缺料、更新快照和真实文件输出保护。CLI 示例可使用 Windows 或 Linux，核心可使用 Wasm GC 或 JavaScript。

开发和技术文档使用 AI 辅助。这里的运行结果可供参赛者复核并用自己的语言准备申报材料。
